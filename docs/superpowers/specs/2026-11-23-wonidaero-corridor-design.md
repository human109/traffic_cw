# 원이대로 예측 대상 확장 — 설계 (short)

- 날짜: 2026-11-23
- 상태: 승인 대기 → 승인 후 계획(`docs/superpowers/plans/`) 작성
- 근거 요청: 사람 "창원대로처럼 원이대로도 예측 대상으로"

## 의도

원이대로(명곡교 → 가음정사거리, 출근 방향)를 창원대로와 같은 방식으로 수집·집계·예측·평가한다. 두 도로의 수집 안정성과 모델 성적은 **도로별로 따로** 볼 수 있어야 한다.

## 목표 / 비목표

- 목표: 원이대로 구간(W1…, 상류 참고 구간 있으면 W0) 정의, 링크 표, 11/19 이후 원본 재적재, 기준 모델 3종 예측·평가, 대시보드 도로 선택, 도로별 수집 성공률.
- 비목표: 원이대로 전용 모델·집계 규칙(창원대로와 같은 규칙 사용), 반대 방향 예측, 도로 간 상호 영향 특성(Slice 2 이후 검토).
- 실패 조건: 원이대로 추가로 창원대로의 Slice 0 판정·기존 평가 수치가 바뀌는 것.

## 접근 (사람이 B 선택)

| 안 | 내용 | 판단 |
|---|---|---|
| A | 구간 행만 추가 | 성공률·평가가 두 도로 합산 → 도로별로 볼 수 없음 |
| **B** | `road_segment.corridor` 열 추가 | **선택.** 도로별 성공률·평가·화면, 세 번째 도로도 같은 방식 |
| C | 도로별 DB·설정 분리 | 코드·운영 두 벌, 제외 |

## 결정

- **C-01**: `road_segment`에 `corridor TEXT NOT NULL DEFAULT '창원대로'`. 기존 행은 기본값으로 이전(운영 DB는 `ALTER TABLE ... ADD COLUMN` 마이그레이션, 백업 선행).
- **C-02**: 저장 범위 `its_store_road_names`에 `원이대로` 추가(양방향 저장, 원본은 이미 전체 보관). 11/19 이후 원본에서 원이대로 행 재적재.
- **구간 ID**: `W0`(참고, 있으면) `W1…`. 링크 표 생성은 `config/build_segment_links.py`에 원이대로 입력 추가(R-09 결과).
- **켜는 시점**: 11/24 Slice 0 판정 후 `is_target=1`. 그 전에는 링크·구간은 `is_target=0`으로 적재 가능.
- **수집 성공률**: `rate(conn, start, end, corridor=None)` — 도로별(기본은 도로마다 한 행씩). Slice 0 판정은 창원대로 기준 유지.
- **평가**: `model_evaluation`의 전체 집계(segment_id NULL)를 도로별로 나눈다(regime 또는 열 — 계획 단계에서 C-04로 확정).
- **대시보드**: 상단 도로 선택(`?corridor=`), 현재 표·히트맵·성공률·성능을 선택 도로로.
- 등급 경계 40/20은 같은 값으로 시작, 원이대로 실측 분포를 R-06b 방식으로 확인 후 재검토.

## 빌더에게 남긴 것
