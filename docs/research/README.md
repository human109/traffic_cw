# 리서치 문서

`researcher` 에이전트의 조사 결과를 모아 둔다. 규칙은 `AGENTS.md` 8장을 따른다.

- 파일 이름: `R-xx-<주제>.md` (예: `R-01-police-utic-api.md`)
- 샘플 응답: `samples/` (인증키·개인정보를 지운 뒤 저장)
- 리서치 결과로 SPEC을 바꿀 때는 오케스트레이터가 반영하고, 해당 R 문서의 상태를 `반영됨`으로 바꾼다.

## 템플릿

```markdown
# R-xx <주제>

| 항목 | 내용 |
|---|---|
| 상태 | 진행 중 / 완료 / 반영됨 |
| 작성일 | YYYY-MM-DD |
| 질문 | 이 리서치가 답하려는 질문 (구체적으로) |
| 관련 작업 | 이 결과를 기다리는 작업 ID |

## 요약
(3~5줄. 개발 에이전트가 이것만 읽어도 결정할 수 있게)

## 발견 사항
| # | 내용 | 구분 | 확신도 | 출처 (URL, 확인일) |
|---|---|---|---|---|
| 1 | ... | 사실 / 추론 / 미확인 | 높음 / 중간 / 낮음 | ... |

## 구현에 필요한 값
(필드명, 코드값, URL 형식, 단위 등. 개발 에이전트가 그대로 쓸 수 있는 형태)

## 미확인·사람 확인 필요
(실제 API 호출, 승인, 비용 등 사람이 해야 할 일)

## SPEC 변경 제안
| SPEC 절 | 현재 | 제안 | 이유 |
|---|---|---|---|
```
