# R-03 표준노드링크: 창원대로 출근 방향 링크 확인 방법

| 항목 | 내용 |
|---|---|
| 상태 | 완료 (방법 조사 완료, 실제 링크 ID는 사람이 파일을 받아 확인해야 함) |
| 작성일 | 2026-11-18 |
| 질문 | 표준노드링크의 최신 배포처·형식·좌표계·필드 정의는 무엇이며, 창원대로 팔용사거리→성주광장(창원터널 방면) 링크를 어떻게 골라내고, 지하차도 본선·지상 측도가 별도 링크로 구분되는가? 버전이 바뀌면 링크 ID가 바뀌는가? |
| 관련 작업 | C-01(segment_link 시드), D-DAT-01 |

## 요약
- 표준노드링크는 국토교통부가 「지능형교통체계 표준 노드·링크 구축기준」(최신: **국토교통부고시 제2026-344호, 2026-06-25 개정, 2026-07-01 시행**)에 따라 관리하며, ITS 국가교통정보센터(표준노드링크관리시스템)와 공공데이터포털(데이터 ID 15025526)에서 **SHP**로 무료 배포한다. 파일은 `MOCT_LINK`, `MOCT_NODE`, `TURNINFO`, `MULTILINK`로 구성된다.
- 링크는 **방향별로 따로** 있으며 `F_NODE`(시작 노드) → `T_NODE`(종료 노드)가 차량 진행 방향이다. 링크 ID는 **권역번호 3자리 + 일련번호 + 확장자 2자리, 총 10자리 문자**다. 창원시 의창구·성산구는 권역번호 414·415로 보이지만 1차 확인이 아니라서 신뢰도는 중간이다.
- 지하차도는 `ROAD_TYPE` 코드로 구분된다(지하차도 코드 존재). 구축기준은 입체화 구간(고가·지하차도)과 평면 도로를 **서로 다른 링크**로 만들고, 구조 변환점에 노드를 두게 한다. 그래서 용원·삼동·성주 지하차도 본선과 지상 측도는 별도 링크일 가능성이 높다. 다만 실제 파일로 확인하지는 못했다.
- 삭제된 ID는 재사용하지 않는다. 하지만 링크를 분할하거나 삭제하고 새로 만들면 ID가 바뀌거나 확장자가 붙는다. 그래서 **버전별로 ID가 유지된다고 가정하면 안 된다.** 2026 개정에서 노드를 두는 위치가 교차로 중심에서 방향별 진출입부로 바뀌어 대규모 재편 가능성도 있다(영향 미확인). `segment_link.nodelink_ver`, `valid_from/valid_to` 설계가 필요하다.
- 이 환경에서는 its.go.kr 접속이 실패했고, 다운로드는 사람 승인 사항이라 파일을 열지 않았다. **링크 ID·길이·제한속도는 아래 절차로 사람이 확인해야 한다.**

| 노드 이름 | `MOCT_NODE.NODE_NAME` (`NODE_ID`로 조인) | 교차로명으로 구간 경계 확인 |
| 길이 | 최신본의 길이 필드(미확인). 없으면 투영좌표계 geometry 길이(m) | #12. 두 값을 모두 기록해 비교 권장 |
| 제한속도 | `MAX_SPD` (km/h) | |
| 차로수 | `LANES` | 부속차로 제외 |
| 도로등급 | `ROAD_RANK` | 창원대로 등급 미확인 |
| 지하차도 여부 | `ROAD_TYPE == '002'` → 본선(지하차도) | #15, #21. 측도 판정은 같은 교차로를 지나는 평행 링크(`ROAD_TYPE=='000'`)로 판단 |
| 권역 | `STNL_REG` 또는 `LINK_ID[:3]` | 의창구 414 / 성산구 415 (확인 필요, #8) |
| 사용 여부 | `ROAD_USE == '0'` (사용) | 1은 미사용 |
| 연결로 제외 | `CONNECT == '000'` | 램프 제외 |

### 창원대로 링크 추출 절차 (사람 또는 dev-data가 로컬에서 수행)
1. `MOCT_LINK`를 읽고 `LINK_ID[:3] in {'414','415'}`(또는 `STNL_REG`)로 1차 필터링한다. 권역번호가 맞지 않으면 의창구·성산구 행정경계 bbox로 대체한다.
2. `ROAD_NAME`에 `창원대로`가 들어간 링크를 고른다. 누락에 대비해 `MULTILINK.ROAD_NAME`도 조인하고, 지도에서 끊긴 곳이 있는지 확인한다(#26).
3. `MOCT_NODE.NODE_NAME`에서 `팔용`, `반계`, `평산`, `차룡`, `용원`, `삼동`, `교육단지`, `공단본부`, `가음정`, `성주` 등 SPEC 3.3의 교차로명을 찾아 경계 노드 후보를 정한다. 노드명 표기는 SPEC과 다를 수 있으니 지도로 대조한다.
4. 팔용사거리 노드에서 출발해, 직전 링크의 `T_NODE`를 `F_NODE`로 갖는 창원대로 링크를 따라가며 창원터널 방면 체인을 만든다. 역방향 링크(일련번호 ±1)는 제외한다.
5. 지하차도 교차로(용원·삼동·성주)에서는 체인이 두 갈래로 나뉜다. `ROAD_TYPE=='002'` 쪽을 본선(`is_mainline=1`), 평면 쪽을 측도(`is_mainline=0`)로 기록한다.
6. 링크마다 `LINK_ID`, `F_NODE`/`T_NODE` 노드명, 길이, `MAX_SPD`, `LANES`, `ROAD_TYPE`, 배포 버전 날짜를 표로 정리해 `docs/research/samples/R-03-changwon-daero-links.csv`로 저장한다. 원본 파일은 저장소에 넣지 않는다.
7. QGIS 등에서 체인을 지도 위에 그려 출근 방향이 맞는지 눈으로 확인한다.

## 미확인·사람 확인 필요
1. **표준노드링크 파일 다운로드(사람 승인 필요)**
   - 위치: ITS 국가교통정보센터 → 표준노드링크 → 자료실 → 전국표준노드링크 최신본(또는 공공데이터포털 15025526).
   - 회원가입·로그인 필요 여부는 미확인. 받으면 배포 날짜(버전)를 기록한다.
   - 압축은 새 빈 디렉터리에 풀고 저장소 밖에 둔다(약 수백 MB).
2. **확인할 항목**: `.prj` 좌표계(EPSG), DBF 인코딩, 최신 필드 목록(특히 길이 필드명·단위, HistType 등 2026 신규 필드), `ROAD_TYPE`·`ROAD_RANK` 코드 실제 값.
3. **창원대로 링크 표 작성**: 위 추출 절차 1~7을 수행한다. 링크 ID는 이 결과로만 채우고 추측하지 않는다.
4. **권역번호 확인**: 고시 원문(국가법령정보센터 첨부 또는 codil PDF)의 권역번호 표에서 창원시 의창구·성산구 값을 직접 확인한다.
5. **수집 API와 링크 ID 일치 여부**: UTIC(R-01)·ITS(R-02) 소통정보 API가 같은 표준링크 ID(10자리)를 쓰는지, 지하차도 본선·측도 링크마다 속도를 제공하는지 확인한다. 실제 응답에 해당 링크 ID가 나오는지는 API 키가 있는 사람이 호출해 봐야 한다.
6. **2026 개정 반영 시점**: 노드 위치 기준 변경(#24)이 배포 데이터에 언제 반영되는지 국토교통부 디지털도로팀 또는 표준노드링크관리시스템 공지로 확인한다. 반영되면 링크 매핑을 다시 해야 한다.
7. **버전 간 ID 변화 실측**: 가능하면 직전 배포본과 최신본을 비교해 창원대로 링크 ID가 바뀌었는지 확인한다(구버전 확보 가능 여부 미확인).
